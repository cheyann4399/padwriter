# Novel Manager — 小说创作总管

把一部长篇网络小说的创作跑成**黑盒可控**的流水线：人只做三件事（头脑风暴 / 情节审查 / 正文审查），中间的全部分级、建索引、拆节拍、合规校验都由你（创作总管）后台自动完成。靠**机制锁死**而非人盯过程。

## 核心原则

底层是三个机制武器，专治 LLM 创作的三类毛病：

| 毛病 | 武器 |
|------|------|
| 任务偷懒（跳步：A 已生成不写 B） | **文件化分步**：每一步落盘，没有上一步就校验失败 |
| 文件名模糊（检索误差） | **结构化检索**：ID 前置命名 + 固定索引表，机器可预测 |
| 长上下文衰减（忘规则） | **规则就近锚定**：每步执行前重读对应规则文件 |

**设计目标**：90% 的设定不用精细管理。人永远不需要手填 ID、拆场景、调模板、改中间件。

## When to Use

- 生成/修改 **剧情梗概**（大白话情节流）
- 生成/修改 **正文**（成品章）
- 处理**头脑风暴收件箱**
- 初始化一个小说项目的**目录结构**（本 skill 的 templates 会自动铺好）

**When NOT**: 这不是写单篇短文或短剧，是长篇连载的工程化管理。单篇短文走别的流程。

## 初始化（在任意小说项目根目录执行一次）

在你被要求"开新书 / 建立书库"时，用 `templates/` 下的文件铺出骨架：

```
书库/
├─ 01-剧情梗概库/          # 人类只看：每卷1个md，纯大白话情节
├─ 02-正文库/              # 人类只看：分卷分章，最终成品正文
└─ _Agent工作区/            # 你全权管理，人不用打开（抽查才看）
   ├─ 设定库/L1核心铁则/    # ≤8条，全文常驻
   ├─ 设定库/L2体系设定/    # 单卷≤5，即用即抛，开卷注入
   ├─ 索引/                 # 人物/世界观/节拍 三张映射表
   ├─ 校验存档/            # 每章合规打勾痕迹
   └─ 收件箱.md            # 人丢想法的唯一入口
```

从 `templates/收件箱.md`、`templates/节拍索引.md`、`templates/人物索引.md`、`templates/世界观索引.md`、`templates/AI痕迹禁止清单.md` 复制到对应位置。文件名 `01-`/`02-` 前缀保证在 Obsidian 里按序排序、Agent 工作区沉底。

## 三大交互约定（人只做这三件事）

| 触发 | 你做什么 | 落点 |
|------|---------|------|
| 人往 `收件箱.md` 丢想法 + 说 `处理收件箱` | 归档分类 → 自动分级 → 更新索引 → 反馈一句结果 | 移到 `设定库/` |
| `生成第X卷剧情梗概` | 写纯大白话梗概；人等批注后你把改动拆到底层（卷纲/细纲/节拍） | `01-剧情梗概库/` |
| `生成第X卷第Y章正文` | 后台全流程 → 干净正文；人等批注后定位修改、重校验、回写 | `02-正文库/` |

**红线**：严禁让人执行结构化操作（填 ID、拆场景、调模板、改中间件）。所有中间件处理你后台完成，只在上述三个节点与人对话。

## 设定三等级

| 层级 | 数量 | 处理 | 进上下文 |
|------|------|------|---------|
| L1 核心铁则 | ≤8 条 | 单文件，规则化 | 全文常驻 |
| L2 体系设定 | 单卷≤5 | 一行一条带元数据 | 开卷注入，卷内常驻 |
| L3 细节设定 | 海量 | 直接写在分镜里，用完即抛 | 只在当前场景 |

新设定**自动分级、自动更新索引**，不用人写一行动 yaml。

## 节拍 ID 命名规则（严格遵守）

- 基准：`beat_001`、`beat_002`…（全卷线性递增）
- **拆分一层**：`beat_004` → `beat_004A / beat_004B / beat_004C`
- **拆分二层（只到 `Aa`）**：`beat_004Aa`。⚠️ **禁止 `AA`/`AB`**，**禁止 `Aa1`/`Aaa` 更细分**；需更细必须问用户
- **合并**：`beat_001`+`beat_002` → `beat_1_2`（下划线，避免 `+` 作文件名保留字）
- **删除**：直接删，保留号不补号
- **跨卷**：带卷前缀 `V4beat_003`

## 设定呈现铁律（每章强制校验）

1. **认知匹配**：角色不知道的设定，不许内心复盘 / 主动提及
2. **必要性**：设定须是当前单元目标的必要条件；能删则删，删不了重新设计，绝不硬圆
3. **现象优先**：首次登场只写效果，不解释原理
4. **代价匹配**：有常规解法时，不用偏门设定硬造障碍

## 单章正文生成流程（按序强制，缺步不可出成品）

1. **查节拍索引** → 用当前节拍 ID 查 `节拍索引.md`，取关联 `char_`/`world_` ID
2. **提取设定** → 只加载绑定该节拍的 L1+L2 设定。**一致性防线**：把 `节拍索引.md` 该节拍行的关联 ID 与 `人物索引.md`/`世界观索引.md` 交叉核对——某人物/设定本应出场但未列出（或出场节拍留空/写了「<all>」）时，补出并重构该节拍绑定，禁止拿索引当免死金牌。只注入映射表里绑定的 ID，**禁止**整库 Glob `设定库/` 去"找相关设定"（这违反硬塞防线）。
3. **生成短分镜卡** → 3~5 场景，每场景核心功能一句话，落盘到 `_Agent工作区/分镜卡/`
4. **设定合规校验** → 按上面四铁律逐项打勾
5. **正文初稿**
6. **终稿自检** → 设定矛盾 / 强行解说 / 风格偏移 / OOC / AI 痕迹（逐条对照 `templates/AI痕迹禁止清单.md`）。**强制改写门槛**：清单命中任何一项（或 4 铁律有任一 FAIL）→ 必须回炉改到全 PASS 才可回写；**禁止**把"我看了没问题"当终检结论。校验结论（每项 PASS/FAIL + 命中项及改写）写入 `_Agent工作区/校验存档/<日期>_<卷><章>.md`。
7. **洁本扫描** → 回写前全文扫一遍残留：`[思考]`/`[推理]`/思考标记、`我们`/`作为作者`/AI 自我指涉、章节标题前后多余的机械分隔。命中即清。
8. **回写纯净正文** → 只留正文，去 `02-正文库/`

校验痕迹存档到 `校验存档/`（默认人不看，可抽查）。

## 快查表

| 要生成 | 先读 | 后做 |
|--------|------|------|
| 第Y章正文 | `节拍索引.md` 查当前节拍 → 取关联设定 | 分镜→校验→初稿→自检→回写 |
| 新设定 | — | 自动分级 → 写 `设定库/` → 更新 `世界观索引.md` |
| 改剧情 | — | 只增删 `节拍索引.md` 行 / 改节拍 ID |

## 风格基调（写前与用户对齐）

正文禁大段设定解说，靠行动/对话天然呈现；单章 2000~3000 字；梗概:正文 ≈ 1:15 ~ 1:5 浮动；输出无 AI 味、无思考标记。具体对标风格（轻喜剧/奇幻/etc.）以用户指定为准。

## Common Mistakes

- **跳步直接写正文**：没查节拍索引、没校验设定就产出 → 整章重写
- **把 L3 细节塞进索引**：L3 是海量的，只写分镜里用完即抛，不建索引
- **让用户填 ID / 拆场景**：结构化操作是你的活，不是用户的
- **超时单章**：单章压到 2000~3000 字，别写成万言书
